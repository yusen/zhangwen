# 模型自然语言修改

## 目标

把用户自然表达转换成可验证的 `model_edit_plan_v1`。自然语言理解保持高自由度，代码执行保持严格边界：用户不需要填写对象 ID、法向量、坐标或代码位置，这些内部信息应从项目源码、模型索引、项目记忆和最近对话中推导。

## 理解原则

1. 默认用户正在谈当前活动项目，不因省略“当前模型”而切换项目。
2. 结合整句和对话理解指代、倒装、省略、同义词、相对位置与多轮修正，不按关键词逐字段读取。
3. 优先用 `model-index.json` 中的稳定对象和表面 ID 定位对象，再读取相关源码块确认几何语义。
4. 用户明确要求什么就修改什么，不主动增加未提出的功能。
5. 对可从模型确定的信息直接推导；只有目标存在重要歧义、几何不可行或请求超出能力边界时才追问。
6. 用户说“字改成两行”时，应关联待处理或唯一可匹配的已有刻字；用户指定行数或换行时执行多行排版，文字过长接近表面容量时可自动换行。
7. 多个对象都可能匹配“这个孔、那个面、它”等指代时，说明候选对象并请用户确认，不随意选择第一个。

## 机械修改语义

- 将“圆角、倒圆、R2、圆角半径 2mm”解析为 CadQuery `fillet`；数值表示圆角半径。
- 将“倒角、切角、C2、45° 倒角”解析为 CadQuery `chamfer`；数值表示倒角尺寸，角度只在当前几何与实现能够明确表达时使用。
- “边线、最高处的边、靠近某面的棱边”等是目标边描述，不是刻字位置。优先用模型索引、相邻表面、方向、高度和长度定位稳定边。
- 如果两条或更多边都符合描述，返回候选边的中文位置说明、相邻表面和必要的稳定 ID，请用户选择；不得默认修改第一条边。
- 开孔、封孔、孔径调整、壁厚调整、硬件移动、结构删除同样属于实体结构修改，必须先验证目标和几何可行性。
- 用户同时提到刻字和机械结构时，按最新明确动作拆分或追问先后顺序；不得把圆角、倒角、开孔等请求伪装成刻字补充。

## 项目边界

- 只读取和修改当前项目目录中的主 CadQuery 源码副本。
- 对 `design_mode: "structural_part_project"`，主源码固定为当前项目的 `structural-parts.cq.py`；允许修改其中一个或多个结构件对象，但不得把 15 mm 并排预览位置解释为真实装配关系。
- 公共模板、服务器代码、硬件库、其他项目、`ZW-CAD-code`、`ZW-CAD` 和 `Adam-CAD` 均为只读。
- 不接收或输出任意绝对路径、父目录跳转或其他项目路径。
- 首次建立项目时可读取完整源码；后续优先使用项目记忆、模型索引、修改历史和相关源码块。
- 每个计划必须携带当前源码 SHA-256；哈希变化后必须重新分析，禁止覆盖较新的项目版本。

## 工作流程

1. 读取当前 `project.json`、主源码、源码哈希、`model-index.json`、`project-memory.json` 和最近修改记录。
2. 将用户要求解析为意图摘要、稳定目标 ID、结构化操作和需要修改的源码块。
3. 对每个代码改动生成有充分上下文的精确 `old_text/new_text` 补丁。`old_text` 应在当前源码中唯一匹配。
4. 按当前源码哈希应用补丁到暂存区，不直接覆盖正式源码。
5. 依次执行项目范围、补丁一致性、Python AST、禁用 API、CadQuery 构建、STEP/STL、mesh、包围盒和体积检查。
   - 独立结构件项目还要验证 `structural_parts_v1` 列表仍完整、稳定 ID 未意外丢失、整体预览不可打印、每个结构件仍可独立导出。
6. 低影响修改通过预检后可自动提交；高影响修改返回中文摘要，得到用户确认后再提交。
7. 提交后保存修订源码、前后哈希、操作摘要、验证结果和项目记忆；失败时保留原源码、artifact 和预览。

## 输出格式

只输出 JSON 对象，不输出 Markdown 或完整替代文件：

```json
{
  "schema_version": "model_edit_plan_v1",
  "plan_id": "edit-stable-id",
  "project_id": "current-project-id",
  "intent_summary": "把相册斜面上的文字改成两行",
  "source_hash": "64位SHA-256",
  "operations": [
    {
      "id": "update-engraving-1",
      "type": "update_surface_engraving",
      "target_id": "engraving-1",
      "summary": "将已有刻字调整为两行居中排版",
      "parameters": {
        "lines": ["第一行", "第二行"]
      }
    }
  ],
  "patches": [
    {
      "target_file": "model-source.cq.py",
      "old_text": "当前源码中的唯一完整片段",
      "new_text": "修改后的完整片段",
      "reason": "调整已有刻字排版"
    }
  ],
  "risk_level": "low",
  "requires_confirmation": false,
  "memory_update": {
    "facts": ["相册斜面刻字采用两行居中排版"],
    "decisions": [],
    "constraints": []
  }
}
```

缺少重要信息时输出 `status: "needs_input"` 和具体中文问题，并保留已识别的操作草稿。不要要求用户提供内部字段。

## 风险分级

- 低影响：刻字内容或排版、非结构装饰、明确且局部的参数调整。
- 中影响：部件位置、旋转、外形尺寸、安装关系和较大代码块调整。
- 高影响：删除或替换硬件、增加或删除开孔、改变底壳/上盖/主体结构、壁厚或关键固定结构。
- 高影响操作必须设置 `requires_confirmation: true`；确认前只写暂存区。
- 所有会改变实体结构、边线、孔槽、壁厚或硬件安装关系的操作都必须设置 `requires_confirmation: true`；圆角和倒角即使范围局部也不得自动提交。
- 待确认计划由后端绑定到当前项目和源码哈希；确认轮只执行服务端保存的计划，不接受客户端重新提交或替换补丁。

## 代码安全

- 只允许导入 `cadquery`、`math` 和 `json`。`json` 仅用于 `json.loads(...)` 等内存字符串解析，以兼容通用盒子项目源码；禁止 `json.load(...)`、`json.dump(...)` 等文件对象接口。
- 禁止通过 CadQuery 的 `importers`、`exporters` 或 `importStep`、`importDXF`、`exportShape` 等接口自行读写模型文件；STEP/STL 只能由后端受控构建器导出。
- 禁止文件读写、网络、系统调用、子进程、动态导入、动态执行、反射、双下划线属性和解释器全局状态修改。
- 不把 API key、token、密码、完整模型源码或敏感配置写入项目记忆。
- 不允许 LLM 指定实际文件系统写入位置；后端项目存储层决定唯一目标路径。
- 补丁中的目标文件必须等于当前项目主源码文件名。

## 验证

- 验证源码哈希一致，拒绝过期计划。
- 验证每个 `old_text` 存在且唯一；不唯一时要求更完整上下文。
- 验证结构化操作、补丁内容和风险级别一致。
- 运行 Python AST 与 CadQuery 真实构建；没有通过构建不得提交。
- 正式 Artifact 刷新失败时恢复提交前源码和项目记忆，不把源码已变但预览仍旧的状态报告为成功。
- 比较修改前后包围盒、体积、实体数量和 mesh，异常变化应阻断或升级确认。
- 对 `fillet`/`chamfer` 验证目标边数量、修改前后体积和边界；构建失败或圆角半径超过局部几何容量时给出可行范围，不自动改小。
- 确认提交只生成当前项目新修订，公共模板和其他项目哈希保持不变。
- 结构件项目必须逐件比较实体数量、包围盒、体积和 mesh；整体并排预览的变化不能替代单件验证。
