# 需求发现方法

## 目标

把模糊想法转成可验证的问题定义，而不是替用户过早决定答案。

## 检查顺序

1. 确认谁会使用、在什么场景使用、要改善什么。
2. 区分必须满足、可以取舍和暂时未知的内容。
3. 为成功标准补充可观察结果、范围和时间边界。
4. 将安全、预算、材料、空间和学习目标列为显式约束。
5. 已确认内容写入共享项目事实，未确认内容保持为待决项。

## 提问规则

- 每轮只提出一个最高影响的具体产品决策问题；用户回答后自然承接并直接问下一个必要问题。
- 不询问是否继续、怎么继续或是否还要补充，不把访谈流程交给用户管理。
- 优先给可比较选项，同时允许用户直接用自然语言回答。
- 不重复询问已经存在于共享事实或确认产物中的信息。
