# ZW-DEVICE-LAB-001 — 双板项目实物仿真与代码部署

状态：实现完成且真人验收待用户（2026-07-30）

## 目标

掌问在项目立项方案确认后，依据已确认的硬件方案、BOM、IO 映射和项目描述，自动创建该
项目的整套实物仿真场景；用户不需要再次手工选择一块固定演示板。场景中的主控只允许：

- `seeedstudio/xiao_esp32s3_sense`
- `dfrobot/dfrobot_k10`

外接传感器、执行器、供电和连接器件按立项内容进入场景。已确认代码可通过两个同级部署
通道上传并运行：USB 串口或 ESP-Claw。ESP-Claw 的运行时固件安装仅用于首次初始化或
恢复，不是日常代码上传流程。

## 用户纠正与语义冻结

- 2026-07-30：用户指出原实现把“仿真”误解为手工选择固定板型的设备实验室。正确语义是
  立项确认后，由掌问从项目事实自动投影出主控、外围器件、连线和可调试通道组成的实物场景。
- 2026-07-30：用户指出原实现把 ESP-Claw 误解为应用固件安装。正确语义是 ESP-Claw 与
  USB 串口同为代码部署通道；安装 ESP-Claw 运行时只是独立的专业维护操作。
- 以上两点优先于本任务早期记录；不得再用手工板型选择或应用包安装替代它们。

## 不可变边界

- 不创建 `ZW-017`。
- 第三种主控板不得进入活动目录、AI 推荐、项目立项、场景生成、仿真或代码部署；历史项目
  可只读保留，但在显式迁移前不得执行设备操作。
- `unihiker-k10` 与 `hw_seed_unihiker_k10` 只作为 K10 的读取兼容别名，界面只显示规范 ID。
- 外围器件不受“两块主控”数量限制，但不得被误识别为第三块主控。
- 场景只从已确认的项目事实生成。没有已确认立项、无法唯一确定主控、存在多主控或含第三种
  主控时失败关闭，并给出可修正原因。
- USB 与 ESP-Claw 都只消费已接受且运行时匹配的 CodeRun；两者共享确认、幂等、取消、
  回读验证和操作结果，但各自使用独立目标与安全握手。
- ESP-Claw 首版在专业模式采用受限 `TRUSTED_LAN_MANUAL` 配对：Web/MCP 必须指向同一私网 IP
  或 `.local` 主机，禁止 URL 凭据和不安全路径，并要求用户确认受信 LAN、Admin Mode 与精确
  板型。它不是自动发现或设备认证；握手、板型/运行时或回读能力不满足时，在写入前失败。
- 日常 ESP-Claw 部署不得调用 `esptool`、整片擦除或 `INSTALL_APPLICATION`。固件初始化/
  恢复继续保留独立高风险确认，且本任务不执行真实设备操作。
- 中央项目实物仿真可以替换可见工作区，但主对话组件保持挂载；右侧一级 Tab 仍为
  “工作 / 产物 / 设备”。
- Wi-Fi 密码和令牌不持久化；配对端点只保存在本机设备注册表，不进入项目导出、参数版本、
  代码、日志或测试夹具。

## 契约与实现方案

### 1. 立项驱动的场景投影

- V29 保存不可变 `DeviceLabSceneV1` 快照：项目、立项版本、规范主控、器件、连线、来源、
  告警和 revision 指纹。
- 立项确认时尝试物化首个场景；读取或启动仿真时从最新已确认项目事实确定性重投影并按
  revision 幂等保存。
- 优先使用已确认规格中的 BOM/IO 映射；缺少规格时允许从已确认硬件目录与立项内容创建
  场景，并明确标记“连线待确认”，不能编造引脚。
- 仿真运行绑定完整场景 revision 和快照，板型由场景导出，API 不接受手工 `boardId` 覆盖。
- Wokwi Elements 只负责器件外观和交互；本地功能引擎或受控 QEMU 负责状态与计算。

### 2. 同级代码部署通道

- CodeRun 增加显式运行时：`MICROPYTHON` 或 `ESP_CLAW_LUA`。智能工程师必须根据项目事实
  生成对应运行时代码，不能把 MicroPython 代码伪装成 ESP-Claw Lua。
- 统一代码部署请求采用判别通道：
  - `USB_SERIAL`：绑定既有串口 `sessionId`。
  - `ESP_CLAW`：绑定已人工配对并通过只读能力握手的 `endpointId`。
- 旧 `/devices/upload` 保持 USB 兼容；新的统一部署入口负责两种通道，操作仍归类为
  `UPLOAD_CODE`，不会进入固件安装状态机。
- ESP-Claw 部署使用版本化脚本路径，执行写入、读回 Hash、异步 Lua 运行和 job 结果验证；
  取消、超时或验证失败需要清理暂存并保留旧版本。
- USB 串口、ESP-Claw、终端、Flash/运行时恢复和参数同步按目标互斥。待恢复的部署请求必须
  持久化通道、目标、CodeRun 与 operation，禁止跨通道误重试。

### 3. 图形化仿真与参数调试

- 中央“项目实物仿真”展示立项生成的主控、外设和连线，并允许仿真/真机调试切换。
- 场景生成与其 revision 绑定的动态调试档案；外接传感器自动生成通用功能输入，外接执行器
  自动生成需解锁、断线归零并受可保存上限约束的通用功能输出，不虚构真实物理单位。
- 模拟传感器可使用滑块、数值、开关、波形或媒体夹具；真机原始读数只读，只允许修改档案
  声明的校准、阈值和采样参数。
- 执行器控制要求显式解锁，并实施范围、刷新率、停止、断线归零和看门狗限制。
- 参数先保存为不可变项目版本，再明确应用到仿真或同步到设备；未实现调试协议的固件不得
  获得虚假的图形化调参能力。

## 可观察验收

1. 确认一个 K10 或 XIAO 项目立项后，API 自动得到含项目主控、外围器件和连线来源的场景；
   仿真启动请求不出现板型选择字段。
2. 未确认立项、第三种主控、多主控或无法唯一确定主控均在创建任何运行前失败关闭。
3. 场景 revision 确定且不可变；相同事实不重复写入，立项/BOM/IO 变化产生新 revision，旧运行
   仍保留其原始快照。
4. 设备页把“USB 串口”和“ESP-Claw”放在同一代码部署区，二者都消费当前已接受 CodeRun；
   ESP-Claw 不藏在应用安装或专业固件区。
5. ESP-Claw 部署证明配对、握手、板型/runtime、文件回读 Hash 和异步运行结果；任一门禁失败
   时零写入，且代码路径不调用 `esptool` 或应用安装。
6. ESP-Claw 运行时初始化/恢复在专业维护区独立显示，不能冒充当前 CodeRun 的上传结果。
7. 项目实物仿真画布展示立项外设与连线；K10/XIAO 板载能力和 XIAO SD/GPIO21 冲突规则生效。
8. 参数版本、仿真应用、真机同步与执行器安全限制均有 Fake transport/功能模型自动测试。
9. 中央工作区往返后主对话消息、草稿、附件和滚动状态不丢失；界面不存在第三种主控。
10. 测试不连接真实设备，不执行真实上传、复位、Flash、擦除、安装或公开发布。

## Decision Log

- 2026-07-30：规范主控 ID 固定为两块板；旧 K10 ID 只在输入边界规范化。
- 2026-07-30：场景是项目事实的不可变投影，不是用户在实验室里另选一块演示板。
- 2026-07-30：ESP-Claw 是 `UPLOAD_CODE` 的部署通道；`INSTALL_APPLICATION` 只服务运行时
  初始化/恢复，两条状态机和安全确认互不复用。
- 2026-07-30：ESP-Claw 的可编程层按官方能力使用 Lua；没有兼容 Lua CodeRun 时失败关闭，
  不把既有 MicroPython 文件直接发送给设备。
- 2026-07-30：Lua 本地验证只称静态结构校验；表达式级错误由远端运行结果检出并触发停止与
  恢复，不能把自研 block/括号检查称为完整 Lua parser。
- 2026-07-30：手动双端点配对只在专业模式挂载；普通模式只消费同项目板型、READY 且地址
  脱敏的既有目标。项目包扫描阻止私网/`.local` URL 和 ESP-Claw 本机会话标识。
- 2026-07-30：ESP-Claw managed job name 只按项目稳定生成，避免同一设备的 IP/`.local` 别名
  留下并发任务；未知、孤儿和退出超时状态一律失败关闭并提示人工急停。
- 2026-07-30：ESP-Claw 文件恢复不能以 HTTP 成功作为完成证据；恢复旧文件必须逐字节回读，
  删除新文件必须回读为不存在，之后才能记录 `rollbackOk=true`。
- 2026-07-30：Wokwi Elements 只承担显示；计算与状态由本地受控引擎承担。
- 2026-07-30：没有确认 IO 映射时显示待确认告警，不从自然语言猜测危险引脚连线。
- 2026-07-30：QEMU 只接受固定版本与 Hash。仓库未随安装器提供可验证二进制前，只能如实
  标记组件未安装并使用功能模型，不能声称固件级 QEMU 已交付。
- 2026-07-30：所有真实 ESP-Claw、串口、参数同步、Flash 和硬件测试保留外部确认点。
- 2026-07-30：V2 的“选择并添加电子器件”在普通与专业模式都直接打开本地器件选择器，不切换
  中央工作区、不发送聊天消息；保存后刷新项目硬件投影和进度，主对话保持原实例挂载。
