## 目的与完成后的用户结果

掌问现有桌面端按工程模块和旧 UI Contract 组织，已经具备项目、AI、硬件知识、代码、CAD、
仿真、参数、设备和交付能力，但用户无法沿着一条清楚路径感受到“作品正在成为真实物体”。

本任务在同一平台内核上重建创作端。完成后，用户从“我的作品”进入一个双栏工作台：左侧持续
与掌问对话，右侧按“创意与方案 / 数字原型 / 3D 结构 / 实物运行”推进；顶部始终显示作品状态、
验证等级和唯一下一步。方案确认后自动生成数字原型，仿真通过后才允许执行实物动作，最终产生
包含方案、代码、参数、结构、设备兼容、证据、限制和恢复方法的可复现作品包。

本任务不是换配色或继续修补 `V2AppShell`，而是建立新的 Creator V3 产品壳、状态投影和完整纵向路径。

## 新共享契约

M1 先在 `packages/contracts` 与 Pydantic 边界中建立以下严格契约，UI 与服务不得复制字符串：

- `CreatorStage`：`IDEA_SOLUTION | DIGITAL_PROTOTYPE | STRUCTURE_3D | PHYSICAL_RUN`；
- `CreatorPhase`：创意、目标待确认、方案待确认、数字原型、仿真、连接、部署、真机验证、验收、交付；
- `VerificationLevel`：整数 0–6，并附证据摘要；
- `CreatorJobStatus`：排队、运行、待确认、成功、失败、取消；
- `CreatorNextAction`：单一主动作、前置条件和受控原因；
- `CreatorWorkspace`：一个作品工作台的统一只读投影；
- `GoalRevision`、`SolutionRevision`、`AcceptanceScenario`、`EvidenceRecord`；
- `DevicePackageRevision`、`DeviceInstanceSummary` 和动作能力；
- `CreatorCommandRequest/Response`：项目版本、幂等键、命令参数和最新投影；
- `CreatorEvent`：任务、遥测、证据、设备和投影变化的 SSE 事件。

所有 Pydantic 边界 `extra="forbid"`。`nextAction`、阶段解锁和验证等级只由服务端投影，客户端不能自行推断。

## API 方向

最终路由名在 M1 契约测试中冻结，预期形态：

```text
GET  /api/creator/works
POST /api/creator/works
GET  /api/creator/works/{workId}
GET  /api/creator/works/{workId}/workspace
POST /api/creator/works/{workId}/commands/{command}
GET  /api/creator/works/{workId}/events
GET  /api/creator/device-packages
```

现有 Chat、Artifact、CAD、Device Lab 和设备 API 可以继续作为内部能力，但 Creator UI 的主路径只消费
聚合投影和显式命令，避免客户端跨五个服务拼出不一致状态。

## 验收矩阵

### 契约与状态

- 非法阶段、等级、命令和额外字段被拒绝；

- `nextAction` 最多一个且与服务端前置条件一致；
- 版本冲突返回可恢复结果，不覆盖新状态；
- 迁移和回滚保持旧项目内容。

### UI/UX

- 作品首页、双栏工作台、四阶段、抽屉和确认弹窗与 PRD 一致；
- 阶段可查看，受控动作说明禁用原因；

- 不出现旧固定“工作 / 产物 / 设备”一级 Tab、图标轨或全局专业模式。

- 真实设备测试必须标记 `hardware` 并保留确认点。

## Surprises & Discoveries

- 2026-07-31：按原里程碑标签复核时发现，早期 M3 只记录了任务事件，没有可恢复的 Job 关系真值；
  M2 刷新恢复仍可能采用过期本地作品；M5/M7 的部分自动测试绕过了公开边界。现已将这些缺口分别
  固化为 `creator_jobs`、服务端活动作品/阶段恢复、真实 Artifact 文件校验和 HTTP/公开服务验收。
- 2026-07-31：设备包目录曾由 Creator 路由临时拼装，ESP-Claw 在缺少设备上报精确板型时仍可能
  继续预检。现改为版本化设备包注册表，并在配对与每次部署前都要求精确板型握手，缺失或不匹配
  均零写入失败关闭。
- 2026-07-31：交付包仅有等级 6 并不足以证明“可复现材料完整”。导出现在还要求当前方案绑定的
  场景、已验收代码 Artifact、参数、必要结构 Artifact、仿真、连接、部署回读、真机行为与人类验收；
  导入重新验证材料和版本绑定，回执操作者必须同时是导入者和副本最终验收者，并与原验收者不同。
- 2026-07-31：Creator 在 390/720/1280 实际浏览器走查中没有横向溢出；弹窗/抽屉使用焦点圈定、
  Escape 关闭、背景 inert 和触发器焦点恢复。阶段切换及抽屉往返继续保留同一个对话实例和草稿。
- 2026-07-31：设备安装虽然服务端已经先回放操作再校验一次性确认令牌，但客户端最初把令牌放进
  幂等指纹，重新准备安装会生成新 `operationId`。现改为会话、应用和动作的语义意图，并把所有
  未决写操作键持久化；重挂载取得新令牌后仍回放原操作。
- 2026-07-31：旧库 V30 零损检查不能直接比较兼容 repair 前后的非规范状态。迁移现先把受支持
  旧形态规范化为 V29 基线，只冻结 V30 之前的历史表；全部 repair、外键和 Hash 通过后才写一条
  数据库级迁移指标，全新数据库不计入历史迁移样本。
- 2026-07-31：交付导入跨 SQLite 与 Artifact 文件系统，不能依赖单事务宣称原子。现使用持久
  `PREPARING/RECOVERED` 意图日志、确定性项目 ID、即时补偿和启动恢复；同包可安全重试，换包
  复用同一键失败关闭。
- 2026-07-31：M7 全量回归再次证明，编译 `models/cadquery.py` 会在受校验 Board Skill 和可复制
  Hardware Skill 模板内生成 `__pycache__/*.pyc`。仅人工删除会反复复发；加载器现只忽略该目录内的
  Python 字节码缓存，源码/manifest Hash、未知普通文件、路径和符号链接校验不放宽，测试夹具也按
