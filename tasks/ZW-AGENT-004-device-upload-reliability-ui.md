# ZW-AGENT-004 - MicroPython 部署可靠性与设备交互优化

状态：已提交（ZW-AGENT-001 至 005 工程节点）

## 1. 目标

基于真实 K10 日常 MicroPython 上传证据，修复“文件已经写入并回读一致、程序实际运行，但 REPL 管理通道重连超时却整体显示上传失败”的错误语义；把文件部署、设备重启和管理通道恢复拆成可独立核对的结果，并优化右侧“设备”中的上传进度、完成摘要、警告和恢复操作。

## 2. 不可变边界

- 中央区域仍是唯一项目主对话；设备上传、状态和恢复继续位于右侧“设备”或既有日志浮窗。
- 右侧一级 Tab 固定为“工作 / 产物 / 设备”，不新增上传或诊断一级 Tab。
- 日常 MicroPython 文件上传与固件烧录严格分离；本节点不执行 Flash 擦除或固件烧录。
- 云端 LLM 不访问文件、Shell 或串口；本地 Sidecar/Tool Runner 执行受控设备操作。
- 只有最新 `ACCEPTED` CodeRun 可以上传；备份、端口锁、固定 argv、`shell=False`、超时、取消、幂等键和逐文件 SHA-256 回读保持不变。
- 文件传输或哈希校验失败仍是上传失败，并尝试恢复备份；只有写入和回读已经通过后发生的管理通道重连失败可以降级为“部署完成但管理通道待恢复”。
- 自动测试只使用 Fake DeviceTransport，不扫描或连接真实串口，不运行真实 `mpremote`/`esptool`。
- 不把真实端口、设备序列号、备份内容或私有文件写入仓库、测试或交接文档。

## 3. 可观察验收

- `PREFLIGHT/BACKUP/TRANSFER/VERIFY_FILES/RESTART` 均以真实退出码通过后，重连非零或超时不再把文件部署整体标为失败，也不自动覆盖已经回读通过的新文件。
- 操作结果明确区分“文件部署”“设备重启”“管理通道”三项；重连未恢复时显示中文警告、保留可恢复备份，并提示重新扫描/连接或按设备 RST 后重试。
- `runtimeExitCode` 不再复用重连退出码；界面不把管理通道连通误述为用户程序业务效果已验证。
- 在写入、回读或重启之前失败时，仍保留原有失败/恢复语义；恢复失败必须显示明确错误和备份信息。
- 兼容读取既有“回读和重启均通过、重连超时、无成功恢复证据”的历史操作，并以修正后的用户语义展示，不伪造设备业务运行结果。
- 设备页以单一主行动路径呈现“选择已接受代码 → 扫描并连接 → 确认覆盖 → 上传 → 查看结果”；专业模式保留长日志和固件区，普通模式不暴露内部 ID。
- 390x844、720x720、1280x720 下，上传主行动、三项结果、警告和恢复操作无页面级横向溢出或遮挡；`CenterChat` 保持单一挂载，项目草稿不丢，右侧一级 Tab 仍只有三项。
- 后端模拟测试、前端交互测试、契约构建、TypeScript 类型检查、桌面构建、Rust 检查和全量回归通过。

## 8. M5：运行中程序的无硬件复位上传

### 目标

当 `main.py` 正在占用解释器、导致普通 `mpremote exec/fs` 无法进入 REPL 时，上传器先在端口锁内执行有界的 Ctrl-C 安全中断，确认 REPL 可管理后再备份、写入和逐文件回读。完成后只重置 MicroPython 运行环境并显式启动 `main.py`，不得触发 RST/EN、断电、Flash 擦除或固件烧录。

### 验收条件

- [x] 上传步骤明确区分 `INTERRUPT_RUNTIME`、文件部署和 `START_RUNTIME`；旧记录中的 `RESTART` 继续可读。
- [x] 安全中断失败时，在备份和写入前以稳定错误码停止，不自动复位硬件。
- [x] 文件管理命令复用已进入的解释器会话，不因每个 `mpremote` 子命令隐式软复位。
- [x] 文件回读通过后，以 MicroPython soft reset 清理旧运行态并显式执行 `main.py`；上传流程不调用硬件 `reset`。
- [x] 启动失败维持上传原子性：尝试恢复备份并报告明确错误，不伪造成功。
- [x] 右侧设备栏用“安全停止程序 / 启动 Python 程序”呈现新流程，不把它描述成主控重启。
- [x] 后端和前端新增自动测试全部使用 Mock/Fake，不扫描、连接或操作真实串口。
