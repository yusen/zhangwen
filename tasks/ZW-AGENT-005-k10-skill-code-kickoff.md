# ZW-AGENT-005 - K10 Skill 驱动代码与项目开场闭环

状态：已提交（ZW-AGENT-001 至 005 工程节点）

## 1. 目标

把用户提供、现归类于 `references/source-packages/unihiker-k10-micropython-skill/` 的原始包作为行空板 K10 的内置只读 Skill 包接入公共硬件库，让智能工程师在匹配 K10 时实际读取该 Skill、相关 API 参考和最小模板；代码默认收束为单个 `src/main.py`，确需多文件时将完整安全文件集作为同一产物、验证和上传清单；新建项目点击“开始项目”后直接以已填写创意启动主对话 LLM 分析，不要求用户重复输入。

## 2. 不可变边界

- 中央区域仍是唯一项目主对话；右侧一级 Tab 固定为“工作 / 产物 / 设备”。
- K10 Skill 与 BoardProfile 都是目录/Markdown 事实源，不新增数据库表、专家或平行硬件模型。
- 云端 LLM 只接收本地装配的有界文本上下文，不直接读取文件、Shell、串口或设备。
- Skill 文本不能扩大工具权限；固件擦除、烧录及真实设备副作用继续保留确认点。
- 代码产物只包含设备实际需要的安全平级 `src/*.py`，必须包含 `src/main.py`；不把 README、测试或占位驱动混入上传版本。
- 多文件版本按一个不可变 CodeRun/ArtifactVersion 保存、验证、接受和上传；上传继续逐文件备份、写入、SHA-256 回读并按现有规则恢复。
- 项目创意只在主对话出现一次；项目建议路由不是主对话回复，创建后的 kickoff 必须幂等且可恢复。
- 自动测试不调用真实付费 LLM，不扫描、连接或上传真实设备，不执行固件烧录或 Flash 擦除。
- 不清理当前未提交工作树，不编辑或暂存 `tasks/ZW-UX-003-three-expert-system.md`。

## 3. 可观察验收

- K10 硬件档案详情显示绑定的 `unihiker-k10-micropython-engineer`、版本、参考/模板数量和未上板验证状态，不暴露主机绝对路径。
- 内置硬件库保留 K10 Skill 的 `SKILL.md`、`references/`、`templates/`、`examples/` 和验证资料；加载时拒绝路径逃逸、缺文件和校验不一致。
- K10 相关智能工程师请求的 Provider 上下文包含有效 BoardProfile、K10 Skill 身份/revision、匹配参考和模板；非 K10 请求不加载该包。
- 屏幕、传感器、联网、AI 和外设请求能够命中对应参考；K10/M10 边界和 MQTT 未验证说明保留。
- 智能工程师结构化代码默认只有 `src/main.py`；确需模块化时允许安全平级 `src/*.py`，`main.py` 必须引用依赖，所有文件在 Artifact、验证和设备上传中保持一致。
- 任一辅助文件语法、导入、写入或回读失败都使该版本/部署失败；成功上传对完整文件集产生备份与逐文件 SHA-256 证据。
- 点击“开始项目”后，填写的创意作为唯一首条用户消息自动进入当前专家对话并触发一次 LLM；不出现本地模板假回复，也不要求再次输入。
- 创建、kickoff 重试或刷新不会重复用户消息或付费调用；配置/模型失败保留项目和原始创意，并提供基于同一轮次的重试。
- 390x844、720x720、1280x720 下硬件库 Skill 摘要、新建项目及主对话状态无横向溢出，`CenterChat` 保持单一挂载。
