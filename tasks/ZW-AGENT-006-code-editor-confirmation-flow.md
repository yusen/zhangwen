# ZW-AGENT-006 - 代码编辑器与中央确认流优化

状态：进行中（未提交）

## 1. 目标

让 MicroPython 工程代码浮窗以代码编辑器为绝对主体，删除模拟验证要求，只保留真实子进程静态检查和语法检查；正式立项工程暂按“表格式立项书 → 智能工程师执行 → 编辑器内验证并接受”推进，立项书全文使用浮窗查看，中央主对话继续承载 CAD、教案和本地执行授权等确认，右侧“工作”只承担进度、状态和非确认型工程操作。Spec 底层 API 与历史数据保留兼容，但不再作为问题引导师确认立项书后的前台步骤或智能工程师代码门禁。

## 2. 不可变边界

- 中央区域仍是唯一项目主对话；右侧一级 Tab 固定为“工作 / 产物 / 设备”。
- 不新增页面、专家、数据库表或平行任务模型，复用现有 ExecutionPlan、PendingItem、Spec、CodeRun、CadRun 和 LessonRun。
- 代码保存仍创建不可变新版本，409 冲突仍保留 Monaco 草稿和变更摘要。
- 新验证只运行静态与语法两个受限子进程，状态只由真实退出码决定；不执行用户代码、不导入开发板模块、不运行 Mock/模拟逻辑。
- 历史 `SIMULATION` 检查允许读取，但不进入新验证结果、接受门禁或默认 UI。
- 真实设备上传和固件烧录仍位于右侧“设备”，保持各自确认点和安全边界；本节点不操作真实设备。
- 不编辑、覆盖或暂存用户自有的 `tasks/ZW-UX-003-three-expert-system.md` 差异。

## 3. 可观察验收

- 代码浮窗打开“代码”视图时，版本元数据压缩到标题/工具条；文件标签、Monaco 和紧凑保存栏占据主要高度，默认视口不再被大块元数据或提示挤压。
- 编辑器随浮窗可用高度伸缩，变更摘要与保存/放弃操作固定在编辑区底部；窄屏改为单列且无页面横向溢出。
- 新代码验证结果只包含 `STATIC` 和 `SYNTAX`，两项退出码都为 `0` 才进入 `READY_FOR_REVIEW` 并允许接受；任一非零即失败，输出文字不能覆盖退出码结论。
- 中央主对话消息流底部一次只显示一个当前待确认事项，覆盖协调器 PendingItem、执行计划审批、Spec、CAD 和教案确认/退回；代码在编辑器内完成验证与接受，不重复投影中央代码确认卡。
- 右侧“工作”不再提供“确认/接受/退回/确认或处理”等用户确认按钮；仍可查看当前状态、任务摘要、生成动作、运行/暂停/重试等非确认操作。
- 打开确认卡、代码浮窗或右侧 Tab 时，中央主对话只挂载一次，项目草稿、滚动和当前推荐方案保持。
- 390x844、720x720、1280x720 三档完成真实 UI 验收，代码编辑面积、中央确认卡和固定三 Tab 均可达且无重叠。
- 当前硬件机械尺寸、孔位或器件资料不完整时，智能工程师仍可产出当前推荐实现；这类未核实事实只作为后续工程验证事项，不得拒绝整轮生成或引导用户修改原需求。代码、凭据、主机文件访问和设备安全边界继续硬阻断。
- 智能工程师出现 `LOCAL_OUTPUT_REJECTED` 时，中央时间线先显示一句自动恢复提示，再直接复用原需求、原专家和原会话创建恢复轮次，不要求用户点击。连续失败时最多自动恢复三次；达到上限后显示无确认按钮的中文终态，不形成无限调用。
- 行空板 K10 代码生成根据项目已选组件或已确认 Spec BOM 注入机器可读 API 契约；静态检查拦截 `mpython/pinpong` 跨板导入、虚构屏幕/按键/RGB 成员、错误构造与调用签名，但不导入或执行设备模块。
- 问题引导师方案卡同时显示“生成立项书 / 生成教案版本”。路线选择仍持久化并可在刷新后恢复；当前临时流程中，两条路线确认表格式实施基线后都不再生成或等待 Spec，已有智能工程师时直接交接执行。
- 点击问题引导师消息中的“查看立项书”直接打开该立项书版本的既有 Artifact 浮窗，不创建新的聊天轮次，不显示“立项书可以在右侧‘产物’中查看”提示；中央主对话保持单一挂载且草稿、滚动不丢失。
- 确认立项书只确认 Proposal，不自动生成或展示 Spec。项目已有智能工程师时，响应携带一次受控自动交接，桌面立即切换到该专家并以已确认立项书为基线开始执行；没有智能工程师时停在已确认状态，不静默新增专家。
- 仓库根目录提供 `build-installer.bat`；默认只构建并验证 NSIS，安装/桌面 smoke 必须显式传参，不执行签名或公开发布。
