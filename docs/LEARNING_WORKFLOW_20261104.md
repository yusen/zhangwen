# 项目学习与验收

2026年11月4日，按用户在流程评估后提出的“完成”，实现第一批四项：项目定义、项目测试记录、验收与复测、证据和反思归档。延续现有桌面三栏与教师/学生视角，复用原 Project、Conversation、Artifact 和 Hardware Skill。

## 从哪里进入

- 工程或结构工作区：点击「项目进度」，或「项目 → 项目进度与验收」。同一个项目直接进入学习设计师。
- 「问题引导」：填写目标、动作规则、参数、异常处理、约束及逐行验收条件。可以先存草稿，再「确认项目定义」；历史定义可以载入为新草稿。
- 「项目学习」：按模块联调、整机验收、装配复测管理测试项。可从确认的验收条件建立清单，已有相同条目不重复添加，也可自行添加或停用测试项。
- 「成果档案」：添加图片和日志、填写学生反思或教师反馈、导出报告和完整项目。旧材料模板、海报、赛事及智能家居阅读案例保留在「材料模板与案例」预览入口。

## 一个项目怎么记录

1. 在工程工作区保存实际主控、模块和程序。尚无器件也可先定义需求；不强制增加开发向导。
2. 确认项目定义。工程模型与两种结构生成路径读取同一份已确认需求；后续未确认草稿不替换现行定义。
3. 在「实际接线与条件」记录固件/库、引脚/I²C总线与地址、供电方案、装配条件。这里只保存用户输入，不自动推断供电足够，也不恢复负载电流必填检查。
4. 逐项填写测试步骤与预期；测试时核对「本次使用的版本与条件」。可选择当前项目的已保存程序和已生成结构版本，记录预测、实际现象、观察人、结果、解释、修改原因和附件。
5. 保存观察后，原结论及条件保持不变。再次测试追加新记录；历史中可以找到当时的版本组合与证据。
6. 调整需求、主控/模块/资料、程序、接线/固件/供电或相关装配/结构条件后，旧通过项提示「需复测」。整机和装配测试受结构版本影响，模块测试不因单纯装配条件变化失效。
7. 完成后写反思与教师反馈，导出可打印 HTML 成果报告，或导出 `zhangwen.project.json` 完整项目。

保存文件和提交运行不等于实物通过。平台不自动替用户确认设备效果；未测项目保持待测试，缺器件等情况可记录为暂时无法测试。关联旧程序进行测试可以保留事实，但不会因此证明当前程序已通过。

## 对话与保存

学习对话使用「API 设置 → 学习设计师」中的模型配置，只返回简短建议、单个关键问题和可选的定义/测试建议。新生成的项目定义直接填入右侧表单，测试建议直接进入右侧清单，无需点击“采用”。定义核对后确认；测试可展开修改、移除，一次保存整份清单，再记录实际观察。快捷回答点选即发送，输入框中尚未发送的其他文字保留。对话不会自动写入“测试通过”，不会上传文件、运行设备或执行命令。没有模型 API 仍可手工填写全部记录。

已编辑的手工定义不会被新回复覆盖，新定义在右侧另列对照，用户可以保留手工修改或明确替换。原有单项测试、观察和反思草稿保持。未修改的生成定义可以随下一轮建议更新；相同的测试不会重复加入待保存清单或已保存记录。生成草稿按项目保存在本浏览器；刷新或加载项目不自动重放历史建议。对话中的原始建议折叠保存，需要时可在右侧重新编辑，不会直接覆盖已保存历史。

学习对话保存于同项目的 Conversation；学习记录以 JSON 检查点追加到原 Artifact 版本。无新增数据库或硬件静态数组。照片与个人反思不会隐式提供给工程/结构模型；学习模型仅获得结构化定义、条件、测试及近期观察摘要和学习对话。

顶栏保存与 Ctrl+S / Cmd+S 保存当前编辑的表单；测试栏目有待保存的生成清单时可批量保存。不会把对话输入当作已经发送，也不会把定义草稿自动确认为需求。其他栏目未保存草稿仍在本浏览器保留。表单保存后同步已关联的项目文件夹；文件夹权限不足时，本机记录仍保留，顶栏显示同步失败，无需重复发送模型需求或保存已经成功的记录。

并发保存使用预期版本号；发生冲突时保留草稿，先读取最新记录并对照，再明确选择继续编辑当前草稿。不自动重发写入、模型请求或设备任务。学生反思草稿记录自己的身份，刷新后不会被误存为教师反馈。

## 文件夹与迁移

原项目快照新增可选 `workflow` 字段，旧项目无需迁移。保存到项目文件夹后包含：

```text
zhangwen.project.json
学习与验收/
  V001_项目记录/
    项目记录.json
    成果档案.html
  V002_项目记录/
    ...
  附件/
    <证据ID>.jpg
    <证据ID>.txt
```

代码、结构和原硬件资料目录继续由原文件夹保存流程管理。程序/结构来源、条件摘要、附件摘要及内部引用在导入前校验；文件夹写入使用原摘要校验流程。完整项目导入后保留学习对话、定义历史、测试观察和证据；导入的历史观察仍是记录人的历史陈述，不能代表在新电脑重新测试。

报告对用户文本进行 HTML 转义，采用无脚本、无远程资源的内容策略；图片内嵌，方便离线阅读与打印。报告显示历史版本与条件，不把旧观察包装成当前设备验收成功。

## 当前范围

- 图片支持 PNG/JPG/WebP 输入，浏览器压缩为 JPG；单份保存最多500KiB。文本日志支持 UTF-8 `.txt/.log/.md/.csv`，单份最多500KiB。
- 每项目最多60项测试、200次观察、30份附件、100版定义、100条反馈/反思与50轮学习对话；学习检查点上限8MiB，完整项目沿用32MiB上限。超限明确拒绝保存，不截断旧记录。
- 视频、班级管理、账号权限、自动评价、海报和赛事材料生成仍未实现；教师/学生是记录视角，不是权限隔离或身份认证。
- 本次实现软件记录和追溯流程；未进行真实模型验收、硬件运行、加工、舵机带载、机构碰撞或实物装配测试。原有3D/激光能力及其几何限制保持。
- 本机开发版本已更新；未修改发布版本号，未提交或推送 GitHub/Gitee。
