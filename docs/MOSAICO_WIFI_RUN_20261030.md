# Mosaico：掌问生成Lua，WiFi上传和运行

2026-10-30。用户已升级最新版Claw，要求WiFi连接后点击运行，取消USB步骤。本轮不做原生C/C++应用、不编译SDK或刷固件。

## 使用（操作已精简）

首次选好Mosaico并保存项目，在「连接设备」填入板子的WiFi地址。若状态栏提示需设置WiFi运行，点击「设置WiFi运行」，再确认重启并重新连接；已有运行服务时不显示这一步。

日常只需三步：

1. 描述需求，点击生成代码，候选会直接显示在右侧程序区。
2. 审阅代码，点击顶部「保存代码」或文件栏保存图标，接受并保存当前代码。
3. 点击「上传并运行」，等待结果自动更新，再看实物效果。

检测、备份、上传和回读校验自动完成，相同代码跳过上传；任何步骤失败就停止，未知结果不重发。运行默认最长30秒；文件栏「⋯ 代码工具」中，「运行结果」查看日志与上传运行记录，「运行设置」调整时限或单独上传/运行，「我的实际观察」记录实物现象；设备状态与配置由顶部「设备设置」打开。仅自动查询已存在任务，不会自动提交运行。掉线或查询超过时限时，可以在「运行结果」中手动查看最新结果；不会自动重试执行。断开WiFi不会停止板上的程序。

## 实现边界

最新版依据官方 `espressif/esp-claw@519bd95900d29bfc9daf3619ff779753e3153f05`（master，2026-10-27）。HTTP模块提供 `/api/lua/<app_id>/*` 回调，并不提供开箱即用的通用运行接口；本次显式安装的固定Lua服务使用这一模块以及官方 `capability.call` 的 `lua_run_script_async` / `lua_get_async_job` 能力。不是通过自然语言要求设备模型执行。

固定服务只接受32位十六进制请求ID、`temp/zw_<16位项目摘要>.lua`和1–60秒整数时限，不接受代码、任意路径或能力名称。运行路径由 `storage.get_root_dir()` 转换为最新版所需的绝对路径。后台先持久保存提交意图，服务端同一请求ID只调用一次运行能力；设备服务在本次启动内也保留去重记录，不自动替换已有任务。设备运行服务与本次提交没有模型调用。

安装清单由后端读取真实规则和固定源码生成，绑定连接与原文件摘要；客户端不能传入任意文件内容。启动规则只启动固定运行服务，以独立exclusive组长期运行；不含项目代码。发生部分安装、连接变化或回读失败时保留备份与待核对记录，不自动重试或重启。文件恢复仍使用已有设备文件备份功能，先人工核对当前文件和启动规则；移除启动规则后需重启才会停止已启动的运行服务。

运行与普通文件写入共用后端设备互斥锁；前端不再请求Web Serial。每次运行记录设备地址和`boot_id`，回读时设备或启动标识变化就保留原证据并拒绝继续查询，不把新设备同名任务当作旧任务。导入项目保留历史证据，但不恢复局域网连接或运行权限。

Lua候选、安装记录、上传凭证及WiFi任务沿用原Project/Conversation/Artifact和原schema 1便携快照，不新建平行项目库。没有代码版本时，安装记录也进入快照。旧USB历史保持标注，当前工作流不使用USB。内置Hardware Skill已按最新提交更新常用Lua资料；用户已有Skill不被覆盖，缺少新资料标记时只补充读取随包同名Skill资料。
