# 掌问三师端到端操作指南

日期：2026-07-28

适用版本：V2 Studio 工作台

实测项目：`行空板K10桌面电子相册`

## 1. 本轮结论

本轮已在真实桌面应用中完成“自由创意 → 问题澄清 → 推荐方案 → 立项书 → MicroPython 代码 → 本地校验与接受 → 结构意图 → Change Set → 真实 3D 构建 → 交付汇总”的三师协作流程。

- 问题引导师完成需求收敛、唯一推荐方案和立项书。
- 智能工程师读取立项书、K10 Hardware Skill 和已确认参数，生成并接受 MicroPython 代码。
- 结构工程师读取同一项目上下文，生成 K10 装配树、CAD 源码修订和真实 GLB/STEP/STL。
- 项目从 V1 导入基线推进到 V2，中央对话、工程页、结构页和交付页读取同一份项目数据。
- 本轮没有连接实体设备，所以没有执行真实串口上传、复位、Flash 擦除或固件烧录。

## 2. 三师如何独立工作、又如何联动

| 角色 | 独立输入 | 独立工作 | 主要产出 | 不直接执行 |
| --- | --- | --- | --- | --- |
| 问题引导师 | 用户创意、目标、约束、成功标准 | 澄清缺失信息，形成单一当前推荐方案 | 推荐实现方案、项目立项书、已确认事实 | 代码生成、设备写入、CAD 构建 |
| 智能工程师 | 已确认立项书、项目硬件、Hardware Skill、项目事实 | 生成代码，执行静态和语法校验 | MicroPython 工程代码、校验结果、可上传版本 | 结构设计、未经确认的设备写入 |
| 结构工程师 | 项目创意、已确认事实、K10 硬件、机械约束、上游产物 | 生成可审计 CAD 源码修订，确认后调用本地 Worker | 对象树、Change Set、GLB/STEP/STL | 修改代码、串口上传、云端直接操作本地文件 |

三师之间不通过“自由聊天猜测”传递结果，而是通过同一项目的已确认事实、Artifact、Project Version 和受控 `ProjectStructureContext` 联动。云端模型只提出内容；本地 Tool Runner 执行代码校验、CAD 构建和设备操作。

## 3. 开始前检查

1. 使用仓库正式入口启动掌问，底部应显示“本地服务正常”。
2. 设置中已经保存可用的云端 LLM；本轮实测为 DeepSeek。
3. Hardware Skill 库中存在 ACTIVE 的“行空板 K10”。
4. 如需真实上传，先准备 USB 数据线和 MicroPython 设备；日常上传不需要烧录固件。
5. Web 页面如需执行 CAD 或设备任务，必须先完成 Local Bridge 配对并获得对应项目的短期授权；纯 Web 页面不能直接访问本地文件、Shell 或串口。

## 4. 完整操作流程

### A. 新建三师项目

1. 点击左侧“项目”，选择“新建项目”。
2. 输入创意：

   > 用行空板 K10 做一个桌面电子相册：板载摄像头拍照，TF 卡存图，按键切换与自动轮播，需要 MicroPython 程序和可 3D 打印的支架外壳。

3. 项目名使用系统建议的“行空板K10桌面电子相册”。
4. 从本地硬件库选择“行空板 K10”。
5. 参与专家同时勾选：

   - 问题引导师
   - 智能工程师
   - 结构工程师

6. 初始专家选择“问题引导师”，创建项目。

### B. 问题引导师：把创意收敛成可执行项目

1. 第一轮澄清选择：

   - 拍照方式：通过按键手动拍照
   - 轮播间隔：5 秒
   - 附加信息：显示日期/时间

2. 第二轮补充：

   - A 键拍照、B 键切换
   - 时间由用户手动设置并在开机后保持
   - 使用约 60° 的桌面倾斜支架

3. 点击“生成推荐实现方案”。
4. 核对页面只显示一套当前推荐方案，并同时包含实现逻辑和硬件方案。
5. 点击“生成立项书”，打开并核对立项书。
6. 点击“确认立项书”。
7. 系统应显示“已交接给智能工程师”。

完成标志：

- “推荐实现方案”为“已确认”。
- “项目立项书”为“已确认”。
- 智能工程师自动成为下一责任人。

### C. 智能工程师：生成、校验并接受代码

1. 在中央对话中让智能工程师按已确认立项书继续实现。
2. 智能工程师应明确读取：

   - 已确认立项书
   - 行空板 K10
   - ACTIVE Hardware Skill 及其 revision
   - 已确认按键、轮播和时间参数

3. 如果出现“本次生成未通过本地校验”，等待系统按原需求自动重试；不要为了迎合错误而改写用户需求。自动恢复达到上限后，再点击“按原需求重试”。
4. 生成成功后，打开“MicroPython 工程代码”浮窗。
5. 核对文件列表，本轮产出为 `src/main.py`。
6. 点击“验证并接受代码”。
7. 等待以下两项均通过：

   - STATIC：静态凭据、宿主能力和 Board API 检查
   - SYNTAX：Python 语法检查

8. 页面显示“当前版本已接受，可在设备页上传”后关闭浮窗。

完成标志：

- 代码产物状态为“已确认”。
- CodeRun 状态为 `ACCEPTED`。
- 项目状态显示“可上传”。

### D. 代码上传：只在连接真实设备后执行

进入“工程 → 设备”，上传步骤固定为：

1. 选择已接受代码。
2. 点击“扫描设备”，选择目标串口。
3. 建立连接；连接只完成安全附加，不应无故复位或擦除 Flash。
4. 点击“上传并运行”，在确认点同意本次日常 MicroPython 上传。
5. 本地 Runner 接管运行态，逐文件写入并回读哈希。
6. 上传通过后启动 `main.py`。
7. 在只读串口终端查看 MicroPython 报错和运行输出。

“固件烧录”是独立高风险流程，不是日常代码上传步骤。本轮实测没有连接实体设备，因此只验证到“已接受 v1 → 等待扫描并连接设备”，没有执行串口写入。

### E. 结构工程师：从项目上下文生成真实 3D

1. 在中央对话选择“结构工程师”，发送：

   > 请读取当前项目已确认立项书、K10 硬件和代码上下文，生成约 60° 桌面倾斜、可 3D 打印的 K10 电子相册支架，并进入可本地构建的 CAD 流程。

2. 进入顶部“结构”工作区。当前 V2 的权威执行入口是结构页的 CAD Intent 工作区。
3. 输入一条不重复硬件细节、用于验证上下文获取的指令：

   > 根据当前项目上下文生成可 3D 打印的桌面结构，沿用已确认机械约束。

4. 点击“生成结构草案”。
5. 核对结构树至少包含：

   - 当前装配
   - 底壳
   - 上盖
   - `unihiker_k10`
   - `unihiker_polymer_lipo_battery`

6. 核对右侧 Change Set 的修改目标为 `/facts/structure/cad_revision`，风险为“低”。
7. 点击“确认源码并生成 3D”。
8. 等待本地任务完成。成功时页面应同时出现：

   - `CAD_INTENT · SUCCEEDED · 100%`
   - `CAD_BUILD · SUCCEEDED · 100%`
   - 三维查看器中的真实模型
   - GLB 下载入口
   - STEP/STL 制造文件

完成标志：

- CAD 修订状态为 `CONFIRMED`。
- Change Set 为“已提交”。
- 项目版本从 V1 推进到 V2。
- 结构页可实际旋转和查看 `preview.glb`。

### F. 交付核对

1. 打开右侧“产物”，应看到四类项目产物：

   - 推荐实现方案
   - 项目立项书
   - MicroPython 工程代码
   - V2 结构 CAD 模型

2. 打开右侧“任务”，核对 CAD Intent 和 CAD Build 均成功。
3. 进入顶部“交付”，核对：

   - 当前交付基线为 V2
   - 版本历史同时包含 V1 导入基线和 V2
   - 代码、文档和 3D 仍属于同一个项目
   - 未完成的实体设备证据和 Release 不被伪造为已完成

## 6. 本轮发现并修复的问题

本轮首次 CAD 构建时，真实的整体模型、GLB、STEP 和多数 STL 已经生成，但一个可选的 `lid.stl` 没有落盘。Worker 仍把它声明为“可用”，导致宿主按安全策略拒绝整批产物并报：

`CAD_BUILD_OUTPUT_INVALID`

修复后的规则是：

1. Worker 先验证文件真实存在且位于宿主管理的 staging 内，再声明为“可用”。
2. 缺失的可选导出标记为 `unavailable`，不会阻断已经完整的 GLB、整体 STEP 和可打印 STL。
3. 越界路径和宿主侧符号链接检查继续失败关闭。
4. GLB 转换结果按真实 `glTF` 文件头和非零大小判定，避免转换进程在文件已完整写入后的清理异常造成假失败。

## 7. 常见问题

### 代码生成被本地校验拒绝

先让系统按原需求自动恢复。确认智能工程师仍读取原立项书、参数和 Hardware Skill；不要让用户重新描述需求来掩盖生成格式错误。

### 页面显示 CAD Runtime 不可用

检查桌面 Sidecar 使用的 Python 环境是否安装并可导入 CadQuery/OCP。不要用假的占位模型代替真实 3D 成功。

### 代码上传被原程序卡住

使用 V2 设备页的安全流程：先附加，再在写入前通过 Ctrl-C 接管提示符、确认身份、取得单端口 Runner 租约，然后上传。不要在连接阶段先执行会被旧程序阻塞的 identity probe。

### Web 为什么不能直接执行本地 CAD/设备

浏览器页面没有本地文件、进程和串口权限。必须通过 Local Bridge 配对，并且只领取 `cad.local`、`device.serial` 或 `device.upload` 的短期项目级授权；云端 LLM 本身始终不能直接执行这些能力。

## 8. 验收边界

本指南证明三师软件流程、真实 Provider 对话、代码本地校验、V1/V2 联动和当前开发机真实 CadQuery 构建已完成。实体设备上传、安装态 CAD、固件流程和 Project Release 仍需各自独立验收，不能由本轮结果替代。
