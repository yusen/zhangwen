## 怎样使用

1. 在智能工程师的「主控板」选择 **ESP-Mosaico（Chat Coding）**。
2. 在中间原对话输入框输入一项明确的小任务，点击「保存任务」，首次保存时选择项目文件夹；右侧同步显示 `chat-task.txt` 与任务历史。
3. 在设备上启动 Mosaico-Claw，配置网络及设备侧模型服务。在设备 Settings → AI Model 查看面板地址，电脑与设备连接同一局域网。
4. 点击右上角原位置的「连接设备」，在弹窗填写完整面板地址。用户设备当前为 `http://192.168.60.126`，无端口默认80，无需添加18789。其他设备以屏幕显示的实际地址和端口为准，点击「连接 Mosaico」；连接后同一位置可查看连接状态或断开；右侧「设备工具」管理设备功能。
5. 核对已保存任务后，点击中间输入框的发送箭头或工具栏「发送任务」。原生 Claw Agent 可能立即生成并执行 Lua；未保存任务不能通过按钮或 Ctrl / ⌘ + Enter 发送。
6. 在中间查看设备回复、右侧查看发送回执并填写「我的实际观察」。会话版通过工具栏「刷新回复」读取历史；旧版连接期间自动收取回复，本机页面每2秒读取已收记录并同步项目文件夹。回执或空闲状态都不能证明硬件任务成功；旧版不提供运行状态。窄屏沿用原分页，在「硬件库」「Chat Coding」「任务与记录」之间切换。

电脑不需要为此安装 ESP-IDF、编译器或 MicroPython。设备须已具备兼容的 Claw 固件和模型配置；掌问不负责安装该固件，也不会把掌问 API 设置或 Key 自动传给设备。设备模型请求仍可能需要网络及模型服务费用。

后续已按用户纠正将原面板功能改为掌问原生控件：右侧「设备工具」操作配置、扫码、记忆、日志、能力、Lua模块和文件，中间沿用Chat Coding并支持附件；不再打开完整设备面板或iframe。详见[集成工具说明](MOSAICO_INTEGRATED_TOOLS_20261030.md)。

这是设备原生 Chat Coding 路线。掌问保存自然语言任务 `chat-task.txt`，经局域网调用设备 Claw WebIM；不将任务伪装成 `main.py`，也不调用串口 REPL、编译、刷写或 Python 上传。切换编程方式会开始另一份草稿，保留原项目和 Python 草稿。

## 固件兼容范围与实板边界

主控资料依据 [Mosaico 官方指南](https://mosaico.espressif.com/zh/guide/) 与 [ESP-Mosaico 硬件指南](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s31/esp-mosaico/index.html)。设备接口依据 [Espressif ESP-Claw 参考提交](https://github.com/espressif/esp-claw/tree/519bd95900d29bfc9daf3619ff779753e3153f05/application/edge_agent/components/http_server)，固定提交 `519bd95900d29bfc9daf3619ff779753e3153f05`。

现兼容该会话版及[旧版WebIM固定参考](https://github.com/espressif/esp-claw/blob/f95614dca7b5b5230d1fadf518d87d0a4cda9ecb/application/edge_agent/components/http_server/http_server_webim_api.c)。旧版使用chat_id及WebSocket实时回复，没有sessions API、服务端历史、启动标识或运行状态。连接依据实际返回结构识别协议，不能确认具体发行固件版本或硬件型号；其他协议明确报错，不自动刷机或改设备凭据。

2026-10-30使用隔离掌问数据库，对用户地址完成HTTP状态、WebSocket握手与17秒心跳后保持连接验收，随后显式断开；设备报告WebIM已绑定。没有向实板发送执行任务。详见[旧版兼容修复](MOSAICO_LEGACY_CONNECTION_20261030.md)。

没有核实通用停止任务 API，因此界面不提供虚假的「停止成功」。断开掌问连接、切换页面或关闭浏览器不会停止设备已运行的规则；停止方式以实际设备的原生功能为准。

真实设备后续待验收：板型/固件发行版本、设备模型可用性、发送小任务、实际回复与屏幕/外设现象、断网/设备重启后的核对与恢复；会话版还需实际会话创建与分页验收。当前仅实测旧版连接，没有实物动作成功、真实模型耗时或课堂实测结论。

## 保存和恢复

复用原 Hardware Skill、Project、Conversation、Artifact 与 schema 1 项目快照。任务保留历史版本；设备原生会话存原 Conversation 的独立标记，不混入掌问本地模型上下文。回执绑定任务版本、摘要、会话，以及会话版提供的设备启动标识；旧版不补造启动标识或运行编号。个人观察独立保存。

项目文件夹根目录保存 `chat-task.txt`、`zhangwen.project.json`，历史任务位于「代码/已保存版本」下；硬件资料沿用原资料版本目录。文件夹同步继续采用摘要预检和回读校验，外部改动不会静默覆盖。快照包含历史证据，不包含设备地址或可继续发送的连接授权；导入副本须重新连接。完全相同快照复用本机工作副本，不覆盖分歧历史。

## 通信与失败处理

- 本地 API 保留精确 Host/Origin、写请求会话检查；浏览器只连接本机服务。
- 设备目标只接受数字 RFC1918 IPv4 的 HTTP 地址，保留显式端口；拒绝公网、回环、域名、路径、账号密码、重定向和代理环境。
- 固定接口：WebIM 状态、基础状态、会话列表/创建/详情、发送和消息读取；旧版另用固定 `/ws/webim` 实时通道，仅保存匹配本项目chat_id的assistant回复。没有任意 URL 代理、命令或文件接口。
- 用户显式点击才发送设备任务；先持久化发送意图，再调用设备。超时或回执不匹配记录为「结果未知」，不自动重发；请求 ID 在本机持久化去重。
- 每次请求有总截止时间和响应大小限制；消息读取有分页及总量限制，不截断后冒充完整证据。
- 会话版设备启动标识变化时要求重新核对连接；旧版不能判断启动标识，实时通道断开即要求显式重连，断线回复无法补读，不自动重连。同一设备地址在本机不同项目间互斥。掌问自身模型仍只有文本和待接受代码权限。
