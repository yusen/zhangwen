# 三师模式与平台更新

2026-10-16。随当前部署版发布；安装与更新以 Gitee master 的具体提交 SHA 为版本。

## 使用

左上原「主控」按钮改为「模式」，可进入智能工程师、结构设计师、学习设计师。顶部品牌旁显示模式名称，右边只显示项目名称。编辑器中的 `main.py` 文件标签保留。原工具栏「结构设计」「教学设计」删除。

智能工程师保留现有硬件、对话、代码、上传与运行工作台。主控选择移至左侧原有主控入口，继续使用对应主控图片。结构设计师、学习设计师有各自的工作区与规划方向，明确标注「待开放」，没有接入模型、LaserMaker 或设计生成能力。

三种模式使用同一项目；切换仅改变界面，工程师编辑器保持挂载，草稿、未发送输入、模块、版本与对话保留。当前模式是浏览器偏好，刷新后可恢复；没有另建项目数据库。运行/上传/刷固件/AI 生成期间禁止切换，避免隐藏当前任务与停止入口。

「检查更新」位于 API 设置和帮助之间。通过一键安装器部署的版本启动时检查一次，也可手动检查；有更新时按钮标记「有更新」。开发目录仅在用户点击时查询，不允许通过网页覆盖源码。

更新流程：先保存项目 → 检查版本 → 勾选确认 → 点击「确认更新」→ 下载、校验、检查依赖、构建 → 标记「待重启」。完成后保存项目，关闭原服务窗口，再从 Windows 桌面图标或 macOS `启动掌问.command` 启动。当前服务不会被后台终止，刷新网页不会重启后端。关闭更新弹窗不取消已经提交的安装任务。

安装沿用 `versions/<Git SHA>`、共享 `runtime`、共享 `data` 和 `current.txt`。旧版本与数据保留；准备失败不切换启动版本。若外部中止安装器，可查看安装根目录 `updates/<SHA>.log` 和原安装器锁提示，排除仍在执行的安装任务后按安装器说明处理。平台不自动清理版本、锁或用户文件。

## 接口与约束

跨端契约先在 `packages/contracts/src/platform.ts` 定义；后端在 `web/updates.py` 实现。

- `GET /api/updates`：本进程版本、部署类型、最近检查结果和任务状态；不访问网络。
- `POST /api/updates/check`：只访问固定的 `zmh1979/ask-with-your-palm` Gitee master 引用；30 秒内共享检查缓存。响应大小和等待受限，拒绝重定向，未使用模型 Key。
- `POST /api/updates/install`：严格接受 `{revision, checkToken, confirmed:true}`。只允许最近 15 分钟已检测的完整 SHA 和确认令牌；禁止额外 URL、命令与字段。

检测受管安装需要匹配 `versions/SHA` 路径、有效 `current.txt`、部署清单和该安装根目录 `data`；支持 Windows/macOS。安装前逐项验证当前部署清单，再以固定参数数组调用清单内安装器，`shell=False`，Windows 隐藏后台窗口，macOS 使用 `/bin/bash`。安装器继续校验远程部署包、复用依赖与准备成功后激活；传入指定 SHA 和不启动参数。

所有接口继承现有精确 Host/Origin 与写请求会话校验；更新器不是模型工具。检测不安装；安装互斥；未保存代码、写盘错误、当前操作未结束时界面不允许确认。安装完成只选择下次启动版本，不触碰正在运行的数据库。这里只下载仓库已发布的部署版本；本地新功能需用户另行明确授权发布，其他电脑才能取得。

## 验证范围

后端使用隔离安装根目录、假代码托管接口与假安装进程验证版本比较、缓存、离线、严格确认、令牌/版本/过期校验、改动源码拒绝、路径保护、Windows/macOS 调用、重复安装、成功/失败、待重启恢复以及数据字节不变。浏览器使用隔离数据与 OPFS，模拟更新响应，不安装真实新版本。既有安装器此前的 Windows 实装与 macOS 两架构 CI 证据仍见 `ONE_COMMAND_DEPLOYMENT_VALIDATION.json`；本轮没有再次进行 macOS 原生安装或生产升级。
