# 主控自检、micro:bit 与多主控开发

2026-11-14，按用户三项要求实现。本轮为本机开发和验证，无提交、推送或版本发布。真实主控验收单独记录，Fake 串口结果不代表实板通过。

## 使用入口

1. 项目器件的主控列表可选择 **BBC micro:bit（V1 / V2）**。首次先使用官方 Python 编辑器准备对应板型的 MicroPython 固件，并备份旧程序；掌问的“固件准备”只说明流程，不调用 ESP32 刷写器。
2. 连接后点击工具栏 **主控自检**，显式执行固定读取程序。先核对主控，再测试模块，最后联合运行。micro:bit 另有“载入点阵测试程序”，只载入编辑器，仍须保存和显式上传运行。
3. 在左侧 **项目主控** 选择 **多主控**，添加并命名主控，例如“传感主控”“执行主控”。各主控为平等卡片，分别选择串口、编写或生成代码、保存历史、自检和点击“上传并运行”。相同型号可添加多次。
4. 切换主控卡片会保留各自的连接、对话、未发送需求和代码草稿。各主控共用“三师共用资料”中的已保存目标、参考资料、结构和程序，私有聊天与未保存草稿不混入。连接期间切换或新建项目会提示先断开设备。关闭网页会释放连接。

目前每个项目最多八块同级主控，沿用原项目存储并增加最多七个 MicroPython 通道。已有 Mosaico Lua/Claw 可继续使用；本轮未增加第二个 Mosaico 通道。多通道提供独立开发与并行连接，板间通信、供电、接线及整机协议仍由项目代码设计并实测，没有自动广播上传或跨板同步启动。

## 自检证据

固定读取项包含运行环境、可用内存、文件系统和板型模块；micro:bit 另读按钮、温度、加速度。缺少接口显示“接口不可用”，返回不合法显示“未通过”，不会虚报全板或外接模块正常。自检不写入设备文件；连接与进入 REPL 会中断当前程序，因此先停止程序再执行。

接口结果与“实际观察”分开，默认尚未确认。记录保存在当前浏览器，按项目、通道和主控隔离，并绑定本次 connectionId；重连后旧结果显示历史记录。点阵测试显示笑脸后清屏，用户核对实物。原逐项测试和学习流程保持，原单主控测试记录不代表附加主控或整机联调通过。

## micro:bit 上传与恢复

复用浏览器 Web Serial，识别 MicroPython 与 microbit 平台后，仅上传已保存清单中的 `main.py`。使用最小文件 API，不依赖 ESP32 的 machine/hashlib/binascii/stat/rename/compile。原文件分块两次读取、在浏览器计算摘要并持久备份后才写；写完完整回读，摘要一致才提交运行。中文代码按 UTF-8 字节传输。

micro:bit 采用直接替换，**不具有原子重命名保障**；中断、容量不足或回读不符会清除凭证并进入需重连状态，不自动重发或回滚。设备下次重启可能执行 `main.py`，不能把“停止解释器”当作物理断电。micro:bit 的设备标识明确使用会话标识，不伪造不可用的硬件序列号。

备份在当前浏览器按项目/通道隔离。附加通道“备份与恢复 → 将此通道备份载入编辑器”只恢复为草稿；用户核对实物后再保存和显式上传。原主通道的 REPL“备份”可下载其上传前程序。不得依赖另一浏览器读取这些本地备份。

## 数据与权限

新增通道检查点复用原 Project/Artifact/SQLite，在原项目内保存主控、模块资料修订、独立代码版本与对话；没有平行项目库。通道主控不可原位替换，避免旧代码与设备归属混淆。代码与对话 CAS 保护、导入摘要校验、资料修订冲突检查保持；冲突保留手工稿，不自动重发模型请求或设备任务。

模型仍只接收文本、资料和当前通道代码，并返回文本与候选代码；不获得设备、串口、命令或系统权限。上传和运行由用户点击。实际端口在页面内互斥，跨页由浏览器原生串口打开约束；不同端口可同时连接。

便携快照、硬件资料导出与可读项目目录包含附加通道；代码位于 `代码/主控通道/<不可变ID>_<名称>/已保存版本/`。共享项目摘要列出已保存通道并明确证据边界，未把原单板流程状态冒充整机状态。V1 保护源不修改，无生产项目代码变更。
