## 使用

1. 选择「ESP-Mosaico（Chat Coding）」，保存项目并选择文件夹。
2. 保持默认编程来源「掌问模型生成 Lua（推荐）」。顶部「API 设置」使用掌问的模型服务，不需要配置板载模型，也不会把掌问Key传给设备。
3. 在中间输入需求，点击生成。回复和候选进入原Conversation/Artifact；候选不会覆盖已接受代码，也不会连接或操作设备。
4. 点击回复中的「查看候选 Lua」，在右侧审阅、修改，再点击「接受并保存 Lua」。Lua草稿在当前浏览器保留，只有接受保存的版本才进入上传清单。顶部普通「保存项目」继续保存项目及已接受历史，不会隐式采用Lua草稿；未接受时项目状态明确显示提示。
5. 右上角「连接设备」填写设备局域网地址，例如用户此前提供的 `http://192.168.60.126`。电脑与板子须在同一局域网，设备须已运行兼容Claw固件；不用连接设备原生模型会话。
6. 点击「查看上传清单」，核对唯一文件、版本、字节数和SHA256，再「确认上传 Lua」。目标为设备存储根目录相对路径 `/scripts/temp/zw_<项目摘要>.lua`。写前校验旧文件摘要、备份到原Artifact历史，写后回读逐字节核对。上传成功不自动运行。
7. 用USB数据线连接板子，在右侧点击「连接USB控制台」，通过Chrome/Edge原生串口选择器选端口。固定115200波特率，以 `help lua` 检查控制台接口，不发送MicroPython raw REPL、重启或刷机指令。
8. 核对USB与局域网连接的是同一块板，勾选确认，选择5/10/30/60秒时限，再点击「USB运行 Lua」。运行前重新核对局域网文件与当前已接受代码的摘要。浏览器仅发送固定 `lua --run --path temp/zw_<项目摘要>.lua --timeout-ms <时限>`。先持久保存运行提交记录，再发USB命令；命令发送、控制台返回和实物通过是不同状态。
9. 查看控制台原始输出，再展开「我的实际观察」记录现象。控制台返回也可能含Lua错误或超时，不标为实物成功。断开USB、局域网或关闭页面不保证停止设备任务；当前不提供未核实的停止接口，时限是向固件提出的运行约束，以实际输出和设备现象为准。

首次建议需求为“生成一个打印Hello的最小Lua测试”。外设、屏幕和长循环后续逐步验证，不将设备原生Claw调用成功替代掌问生成链路。原「设备原生 Claw」仍可在编程来源中手动切换，该路线才需要板载模型API；来源选择在本浏览器记住。两条路线不自动互相发任务。

## 实现与数据

共享契约在 `packages/contracts/src/platform.ts` 先定义。Lua版本、接受指针、上传意图/回读、USB提交与输出保存在同一个项目的原Artifact库；没有新建项目数据库或硬件静态数组。AI对话复用现有 `/projects/{id}/chat`、设置、流式响应和原Conversation，使用明确的 `lua-coding` intent隔离历史。模型请求没有工具或设备权限，服务端不运行生成的Lua。

Lua历史独立于旧 `chat-task.txt` 任务版本，不把自然语言任务当Lua，也不自动转换旧项目。便携快照可选 `luaCoding` 字段含已接受版本、候选与历史证据，仍为schema 1；严格检查版本连续性、接受指针、摘要及上传关联。导入不恢复USB、局域网授权或执行，不把旧回执当作当前板子的执行许可；运行前必须重新连接并核对当前文件。Lua文件副本位于 `代码/Lua/AI候选` 或 `代码/Lua/已接受版本/V号_Lua程序/program.lua`，沿用文件夹摘要预检和不可变文件回读。

设备写入固定为当前项目单个Lua文件及必要的 `/scripts/temp` 父目录；不会修改路由规则、启动项、内置Lua、模型配置或凭据。设备未知写入保持原阻止机制，上传请求ID及提交意图另持久保存在项目中，重启服务后不会重发同一未知请求。串口使用与原MicroPython相同的浏览器互斥锁；不提供自由命令输入、任意shell或后端串口代理。断线/超时不自动重连或重发，日志有界，超限/缺少回显/缺少提示符明确为待核对。

本轮固定依据 `espressif/esp-claw@f95614dca7b5b5230d1fadf518d87d0a4cda9ecb` 的文件HTTP API、`cmd_cap_lua.c`、cap_lua说明和Lua模块文档。网页接口没有已核实的直接执行Lua入口，因此采用用户同意的USB控制台，不伪造HTTP运行API。Lua工具路径是 `temp/*.lua`，文件管理路径是 `/scripts/temp/*.lua`；底层 `/nand` 或 `/fatfs` 由固件处理。

参考资料放在原Mosaico Hardware Skill的 `references/integration.md`。保留已安装用户包；当其尚无新Lua章节时，补充读取同名随包Hardware Skill的固定版本资料，不覆盖用户资料。通用模块文档不能证明当前固件已启用模块；实际库签名、板型和外设能力需在实板核对。屏幕文字API仅支持ASCII，不能臆造中文字体接口。

## 验证范围

协议、模型与设备验证使用Fake，浏览器使用隔离数据库和OPFS，USB由Fake Web Serial模拟；没有真实模型费用、真实设备写入或USB运行。已验证生成不访问设备、不复制凭据、候选需接受、上传清单取消不写、文件回读、有限命令、运行记录、文件夹同步与恢复、来源切换及浅深色1440/1024/375布局。

最终检查和服务状态见同名 `VALIDATION.json`。实板待验：实际USB控制台可达性与提示符/回显、文件命名空间、Lua模块可用性、真实模型生成质量、超时行为及屏幕/外设现象。Fake通过不能替代这些结论。本轮不改版本号、不发布、不安装SDK或刷固件、不读写V1用户库。
