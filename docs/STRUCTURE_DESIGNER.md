# 结构设计师

按用户要求，将 ZW-CAD-intent 项目的结构设计流程接入掌问。点击「模式 → 结构设计师」使用；原 CAD 项目、V1 和已有编程项目保持原样。结构功能随当前部署版本提供。

## 工作方式

结构设计师沿用智能工程师的项目标题、工具栏、色彩、浅深主题、图标、浮窗及响应式标准。桌面为三栏：左侧结构硬件与尺寸资料，中间掌问 AI 对话与下一步确认，右侧结构预览、版本、参数和导出。收起左栏仅扩展对话，右侧宽度与位置保持；手机使用硬件、对话、模型三个页签。模型支持全屏、Esc 退出、旋转、缩放和视角重置。

先新建或保存当前项目并授权本地文件夹。可以在结构硬件浮窗搜索多选，或加入当前智能工程师中有几何资料匹配的主控和模块。编程 Hardware Skill 仍是原资料源，32 份 CAD profile 仅补充几何尺寸、孔位、接口和安装规则；缺尺寸的工程硬件明确列出，不按品牌限制或捏造尺寸。可补充原 CAD 格式 JSON profile，但缺安装资料时仍会阻断建模。

有两条实际可用路径：

1. 在掌问 API 设置中配置模型，描述作品需求，完成需求/BOM/缺失资料确认，再确认尺寸并生成模型。支持继续对话修改、检查和阻断选项。
2. 选择硬件后点击「按所选硬件生成草案」，无需 AI 即可设计这些零件的矩形外壳。此路径只确认所选零件集合，不表示已经完成 AI 产品功能覆盖判断。

右侧可调整毫米尺寸、安装面和平面朝向，应用后生成新的结构版本。可切换整体、爆炸、底壳、上盖和硬件视图，并下载真实 STEP/STL、建模代码和检查报告。未生成真实模型时只显示明确标注的 2D 草案或失败信息，不把调试模型标成真实模型。

## 保存与边界

结构对话和结构版本使用同一项目的原 Conversation/Artifact，独立于编程对话与 main.py 历史。切换模式保留代码草稿、主控、模块和记录。每轮操作写入独立产物目录，调参不覆盖旧模型；版本下拉框可回看历史。结构模式下工程代码无更改时，保存只同步项目文件夹，不新增重复代码版本。

自动同步及「保存」会将结构文件写入已授权项目目录的 `structure/<任务>/<版本>/` 子目录，并将对话、版本及带 SHA-256 的资产保存进项目快照。加载项目文件夹可恢复；导入检查形状、资产清单、路径和摘要，已有不同内容拒绝覆盖。原生目录选择器和跨物理电脑恢复本轮未单独验收，自动化使用隔离浏览器 OPFS。当前单份项目快照上限 32 MiB、结构历史上限 200 版，达到上限时应归档并新建项目。

当前源工具的真实范围是矩形带盖 FDM 外壳。特殊曲面、任意机械结构、真实装配、强度和打印加工验收不在本次能力声明中。结构检查与网格检查分别显示；缺资料、模型连接失败、真实 CAD 构建失败均保留原版本。

## 接入实现

- 前端：`StructureWorkspace.tsx`、`StructurePreview.tsx`、`structure.css`，预览使用本地打包的 Three.js，离开模式释放渲染资源。
- 契约：`packages/contracts/src/structure.ts`；项目快照增加可选结构字段，旧项目格式仍可加载。
- API：`GET /api/structure/catalog`、`GET/POST /api/projects/{id}/structure`，项目所属资产通过固定白名单路由下载。精确 Host/Origin、写请求会话、乐观版本冲突及单结构任务互斥继续生效。
- 运行器：FastAPI 固定启动 `services/structure-cad/worker.mjs`，不启动第二个 HTTP 服务；模型设置通过 stdin 传入，不写入命令行、导出或浏览器。
- AI 只生成结构化意图。CadQuery 源码由可信确定性工具生成，客户端不能提交源码/命令/任意 draft；导入保存的代码也不会直接执行。工作器总时限 300 秒，真实建模子进程时限 90 秒。
- 来源：`docs/structure-source-manifest.json` 记录原项目 47 份文件摘要；未复制 .env、凭据、用户导出、依赖目录或虚拟环境。保留原 Markdown 技能契约，管线接口适配平台模型和项目上下文。

## 部署与验证

真实几何依赖锁定 CadQuery 2.8.0、OCP 7.9.3.1.1、trimesh 4.12.2。启动时先检测已安装版本和实际导入，完整则复用；首次安装会下载几何库。Intel Mac 使用 Python 3.12/3.13 和独立 numpy/numba/llvmlite/nlopt 精确版本，启动入口会选择兼容解释器；其他平台继续按对应条件锁定。一键部署白名单已包含结构运行代码、图片、技能和构建依赖。

开发验证在 Windows 完成真实 CadQuery 构建、STEP/STL 读取、调参、旧模型摘要、同项目编程隔离、项目快照导入恢复、会话和项目归属边界；模型流程使用 Fake HTTP 服务，无真实模型或设备操作。strict 构建、前端/安装器测试和浅深主题检查通过。Intel Mac Python 3.12/3.13 与 Apple Silicon Python 3.13 的 wheel 和依赖解析通过；原生各平台安装与结构导出检查见仓库 Deployment smoke 工作流的实际结果。验证过程记录保留在开发工作区，不随部署版上传。
