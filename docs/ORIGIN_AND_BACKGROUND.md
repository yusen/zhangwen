# 开发的初心与介绍背景

本文说明掌问为什么被做出来、为什么叫这个名字、它从哪来，以及今天走到哪一步。

文中区分三种状态：**已实现**（有代码、可运行、已实测）、**部分实现**（有受限能力，边界写在正文里）、**待开放**（界面或设计已就位，业务能力未接入）。请按这个区分理解本文，不要把规划当成现状。

核对日期：2026-10-27。平台能力以 [`README.md`](../README.md) 与 [`MODES_UPDATES.md`](MODES_UPDATES.md) 为准。

---

## 一句话

掌问是本地部署的开源 AI 造物平台：用自然语言对话替代代码编写与工程流程，让创作者从一句话创意走到可运行的作品。

## 为什么做它

三个变化在同时发生。

| 变化 | 发生了什么 | 对教育的含义 |
|---|---|---|
| AI 重塑知识生产 | 大模型让代码生成变为自然语言对话，技术门槛急剧下降 | 「对话即编程」的时代到来 |
| 新课标呼唤工程实践 | 物联网、人工智能、开源硬件写入新课标 | 但懂技术的师资严重不足 |
| 从「教知识」到「育能力」 | 科技教育本质是培养从 0 到 1 的创新人才 | 评价方式也必须跟着变 |

技术门槛在下降，但对「怎么教、怎么评」的要求在上升。这两件事的交集，就是科技教育当下真正的难题。

## 从一个养伤期间的实验开始

作者是一名高中科技老师，但更喜欢被叫作创客。

2012 年带着 8 个学生去 Seeed 和柴火创客空间谈开源与创客，从一块 Arduino 开始玩起。此后参加数不清的创客马拉松，曾获深圳十大创客人物，并获深圳市政府十万元个人创客资助。2018 年联合发起国内首款开源硬件掌控板，把「人人可编程」交给一块巴掌大的板子；也是人教地图版高中信息技术教材《开源硬件项目设计》的分册主编。

这条路走得越久，越清楚卡在哪里。不是教不会，是进不来。

2025 年 4 月去上海交通大学参加活动，意外脚趾骨折，回家休养。闲下来反而让作者从忙碌里抽身，重新想这件事：如果不要求人先学会编程，能不能让人直接用自然语言，把想法变成能跑起来的东西？

于是有了第一个实验——让大模型直接控制掌控板画圆。「必须学编程才能造物」这个前提，被拿掉了。

## 要解决的具体问题

非技术背景教师长期被拒之门外。三道门槛同时存在：

| 门槛 | 表现 |
|---|---|
| 工具壁垒高 | 开源硬件需 C++ / MicroPython，3D 打印需 CAD 建模；教师需数百小时才能入门 |
| 时间成本高 | 传统流程从需求到调试周期以周计，一次失败就可能耗掉整个学期 |
| 跨学科难协同 | 物理老师不懂代码，美术老师不懂电路，信息老师不懂学科内容 |

两条流程的差距：

```
传统科技教育：学编程语言 → 研究硬件手册 → 设计电路 → 编写代码
              → 调试排错 → 设计 3D 外壳 → 切片打印 → 装配测试
              周期 2–4 周 · 需跨多软件与平台

AI + 科技教育：一句话描述创意 → AI 导师协作引导 → 生成完整方案（代码 + 结构 + BOM）
              周期 一节课 · 自然语言对话完成
```

掌问要实现的就是这个差距下的「做中学」造物工具。

> 关于周期口径：讲台材料中同一处流程对比写作「一节课」，另一处效率对比写作「2 周缩短至 20 分钟」。两者不冲突——前者是课堂场景的整体耗时，后者是单次生成环节的实测用时。平台不对所有项目做统一的倍数承诺。

## 名字来自使用者

| 时间 | 事件 |
|---|---|
| 2025.10 | 向全网征集 AI 超级导师的名字，主题是【掌？】 |
| 2025.11 | 在 Maker Faire 工作坊中，正式确定为【掌问】 |

- **掌**：把创造握在手里，动手做出来
- **问**：以追问引导思考，而不是直接给答案

名字不是内部定的，是征集来的。这决定了掌问从第一天起就是一个面向师生的公共产品，而不是一套内部工具。

## 十四年的路

掌问不是从需求文档开始的，是从一条已经走了十四年的路开始的。

| 时间 | 地点 | 发生了什么 |
|---|---|---|
| 2012 | 深圳 · 柴火 | 带领 8 位学生在 Seeed 公司与柴火创客空间创始人潘昊、Arduino 创始人 Massimo Banzi 第一次谈开源与创客 |
| 2017 | 深圳 · 喜来登 | 作为创客教育专家委员会代表，与 micro:bit 基金会主席 ZACH Shelby 商谈在中国推广 micro:bit |
| 2018 | 上海 · 乐鑫 | 掌控板项目组与乐鑫张瑞兴（CEO）达成联合发起单位，支持国产教育开源硬件 |
| 2023 | 北京 · 中关村 | 掌控相机在第十一届中小学 STEAM 教育大会发布，提出 1320 计划，推动更易普及的中小学 AI 教育生态 |

这条路上最重要的变化不是工具，而是谁能参与创造。

方法论来源是 2016 年提出的创客学习法模型：玩学思做研合一——做中学、做中思、做中研。

## 开发历程

| 阶段 | 时间 | 做了什么 | 关键转折 |
|---|---|---|---|
| 实验验证期 | 2025.04 | 上海交通大学参加活动期间意外骨折，回家休养期间做第一个实验：自然语言控制掌控板画圆 | 证明大模型可直接控制硬件，打破「必须学编程才能造物」的限制 |
| 技术突破期 | 2025.11 | WebSocket 控制掌控板，掌问 1.0 问世 | 实现实时双向通信，奠定本地控制与云端协作的技术基础 |
| 实践检验期 | 2025.06 | 「手搓小智」课例：DIFY + 掌控板 | 把语音交互与硬件控制带进课堂，验证课例形态 |
| 实践检验期 | 2025.12 | Maker Faire 工作坊 + 第二届 AI 教育大会 | 四足机器狗工作坊验证教育场景价值 |
| 架构重构期 | 2026.01–05 | 全面推翻重构为全新掌问智能体 | 从工具升级为智能体，三师协作架构正式确立 |
| 工程扩展期 | 2026.10 | 本地 Web 三师平台扩展 | 工程案例、参数化 3D 与激光图纸进入同一项目 |

第四阶段是重要的转折：从工具变成智能体。前三个阶段的实践让团队认识到，单点工具解决不了「怎么教」的问题——工具解决不了学习设计，也不该由工具承担。

2026 年 7 月，在 2026 世界人工智能大会（WAIC）「智教浦江 2026」人工智能教育实践创新论坛暨第三届中小学人工智能与科技教育大会上，《对话即创造：科技教育（STEM）新范式》作为理念首次正式提出，同期开设工作坊《面向零基础教师的掌问 AI 造物实践》。

## 理念、价值、目标

这三句话后来变成了判断每一个功能做没做对的尺子——一个功能如果不能降低表达和实现的门槛，就不该进产品。

| 层次 | 主张 | 含义 |
|---|---|---|
| 理念 | 对话即创造 | 用自然语言对话替代复杂的代码与工程流程，让创造从一句话开始 |
| 价值 | 创意能物化 | 让抽象的创意变成可触摸的作品：代码、结构模型、BOM 清单、教学材料 |
| 目标 | 人人敢发明 | 让学生、教师、创客、开发者等群体都能在掌问中把想法变成现实 |

## 为什么是三师，而不是一个万能 Agent

以 LLM 作为「智能大脑」、开源硬件作为「物理驱体」，育人逻辑拆成三层：

| 育人逻辑 | 做什么 | 对应思维培养 |
|---|---|---|
| 认知降维：从代码到意图 | 学生用自然语言描述需求，LLM 转化为可执行代码。编程从「语法记忆」转向「意图表达」 | 设计思维、创新思维 |
| 具身锚定：从虚拟到物理 | 开源硬件低成本、易上手、资源多，让 AI 决策落地为物理动作，在真实反馈中建立系统思维 | 批判思维、成长思维 |
| 人机协同：从替代到共生 | LLM 不替代学生思考，而是协作伙伴；学生负责架构设计、调试优化与伦理判断 | 合作思维、关心思维 |

这套逻辑对应「三阶六维」体系：学生完成作品之后究竟学到了什么——工程产物只是结果，理解和判断需要另外观察。

由此拆出三个专业角色：

```
三师协作层 ─┬─ 问题引导师：创意引导、问题定义、需求澄清
             ├─ 智能工程师：硬件方案、代码与程序
             └─ 结构工程师：结构设计、尺寸与装配
                    ↓
用户层：创客 / 学生 / 教师 —— 创建项目 · 澄清方案 · 确认事实
                    ↓
产物管理层：项目级时间线 · 版本化产物 · 中央主对话
                    ↓
最终交付物：ZIP 项目包 · 步骤文档 · 教案与任务单 · BOM 与接线
```

三个师共用同一个项目与同一条时间线，未确认的单稿不进入项目上下文。当前三种模式共享项目与产物，三师自动协同编排仍在规划中。

## 今天的状态

| 模式 | 状态 | 回答什么问题 |
|---|---|---|
| 智能工程师 | 已实现 | 作品怎样感知与运行——硬件资料、程序生成、设备连接与验证 |
| 结构设计师 | 部分实现 | 作品怎样成形与装配——硬件外壳、参数化 3D、激光切割图纸 |
| 学习设计师 | 待开放 | 创造怎样成为学习——问题引导、项目学习、成果档案（界面与模板预览已就位，学习业务待开发） |

| 项目 | 数量 | 说明 |
|---|---|---|
| 支持主控 | 5 款 | 掌控板 2.0 / 3.0、行空板 K10、XIAO ESP32S3 Sense、ESP32-C3 |
| 模块档案 | 253 个 | 传感器 204、执行器 42、显示器 6、电源 1 |
| 内置固件 | 5 款 | 随包提供已固定版本与摘要的官方默认固件 |

已完成实测的案例：智慧农场监测站（土壤湿度 + 温湿度 + 云端上传）、智能垃圾桶（超声波测距触发舵机开盖）、小游戏（描述需求到上传运行六步流程）、AI 智能家居。

尚未完成或需另行验证的：学习生成、保存与导入导出；三师自动任务流转；任意自由造型与任意模型；真实刷写验收；所有硬件与电气兼容性的实物确认。

253 个模块档案不等于 253 个经过实物验证的驱动。模块、主控与代码之间的适配，需要使用者按具体型号自行核对与实测。

## 开源方式

- 一条命令安装启动，无需预装 Git、Node.js 或 Python，服务只监听 `127.0.0.1`
- 用户数据与程序版本分开保存，升级与回退互不影响
- 项目有权授权的原创代码采用 Apache License 2.0，允许使用、修改与商业分发
- 第三方代码、依赖、固件、字体、产品图片与硬件资料保留各自版权，不因本项目采用 Apache-2.0 而被重新授权
