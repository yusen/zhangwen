# Creator V3 证据、交付与复现契约

版本：v1.0

日期：2026-07-31
适用任务：`ZW-CREATOR-001` M7

## 1. 目标

Creator 的交付对象是“可追溯作品”，不是一份未经验证的代码压缩包。只有当前作品达到等级 6，且
存在当前有效的用户验收证据，才允许生成交付包。部署完成、AI 文本或旧作品的历史等级都不能替代
这项前置条件。

交付服务复用既有 `ProjectPackageRepository` 的 Artifact 选择、隐私扫描、确定性 ZIP、导入隔离和
Hash 校验，不建立第二套项目导入器。Creator 外层只增加作品语义、证据摘要、成熟度声明和复现指南。

## 2. 三种交付变体

| 变体 | 用途 | 代码 | 设备日志 | 原作品证据 |
|---|---|---:|---:|---:|
| `SHARE` | 浏览、评审和展示 | 排除 | 排除 | 脱敏摘要 |
| `REPRODUCIBLE` | 第二用户重新完成作品 | 包含受控项目产物 | 排除 | 脱敏摘要 |
| `TEMPLATE` | 从目标和方案开始新创作 | 包含可复用产物 | 排除 | 不包含 |

所有变体都排除证据 `sourceId`、设备会话、端点、真实串口标识和设备日志。模板包不继承原作品的
任何验证证据。

## 3. 外层包结构

```text
*.zwcreator.zip
├── manifest.json
├── privacy_report.json
├── creator/
│   ├── workspace.json
│   ├── evidence.json
│   └── reproduction-guide.md
└── payload/
    └── project-package.zip
```

`manifest.json` 使用 `creator-delivery/v1`，绑定交付 ID、变体、来源作品/版本、目标和方案修订、设备包、
代码/参数/结构版本、证据种类、成熟度以及每个成员的字节数和 SHA-256。`workspace.json` 另包含经严格
校验的 `deliveryMaterials`：当前方案对应的数字场景、已验收代码 Artifact、参数集、必要结构 Artifact、
仿真、设备连接、部署回读、真机行为和人类验收。外层 ZIP 另计算整体 SHA-256，并写入不可变
`creator_deliveries` 记录。

能力成熟度不是固定三项，而是按当前方案声明的能力、设备包能力和当前有效证据推导：

- 使用感知能力时，最多披露 `MVP`；
- 使用响应执行能力且有完整安全/真机证据时，最多披露 `CONTROLLED_BETA`；
- 使用视觉/音频能力时，最多披露 `TECH_PREVIEW`；
- 方案未使用或材料无法证明的能力不进入 manifest。

这些标签是能力边界，不会因一个作品通过验收而自动升级平台成熟度，也不能由调用方直接填写。

## 4. 安全边界

导出与导入均失败关闭：

- 最多 16 个外层成员，单成员不超过 512 MiB，总解压上限 600 MiB；
- 拒绝绝对路径、路径穿越、重复路径、加密成员、符号链接和未知成员；
- 校验 manifest 声明的完整成员集合、字节数和 SHA-256；
- 复用项目包的凭据、令牌、本机路径、私网端点、ESP-Claw 标识和设备日志隐私扫描；
- 导入时重新执行隐私检查，不信任包内 `privacyOk`；
- 凭据、Wi-Fi 密码、令牌、真实端点和设备 ID 不进入 Creator 数据表、复现证据或项目文件。

## 5. 导入与验证重置

导入先完整验证 Creator 外层、`deliveryMaterials` 和版本绑定，再交由项目包服务在同一受控操作中
建立全新项目和 ID 图。随后恢复并重映射可复用的目标、方案、验收场景、硬件选择、数字场景、
代码运行、参数集和必要 CAD 修订，但只保留新的目标确认基线：

- 导入作品使用 `CREATOR` 来源，不作为 Legacy 项目；
- 原作品等级、仿真、设备、部署、真机和用户验收证据全部不继承；
- 导入结果从等级 1 开始，必须在本机重新完成静态检查、仿真、设备、真机和用户验收；
- 包 Hash、导入者、来源交付和来源作品写入 `creator_delivery_imports`，供复现闭环核验。
- 导入由 `idempotencyKey + package SHA-256` 唯一绑定；模糊重试返回同一项目和导入记录，键被换包
  复用时拒绝；
- 跨 SQLite 与 Artifact 文件系统的导入使用持久意图日志：创建项目之前先按认证 subject、
  `idempotencyKey`、请求 Hash、包 SHA-256 和确定性目标项目 ID 写入
  `creator_delivery_import_intents`；
- 正常成功时，导入记录写入和意图删除在同一数据库事务内完成；受控失败立即补偿项目与
  `artifact-files`，进程崩溃遗留的 `PREPARING` 意图在下次启动时清理孤立项目并转为
  `RECOVERED` tombstone；
- tombstone 允许同一包用同一键安全重试，但拒绝换包复用键。任一步验证/恢复失败均不得留下
  可见孤立项目或未归属的 `artifact-files`。

## 6. 第二用户复现

只有 `REPRODUCIBLE` 包可以形成复现回执。服务端同时要求：

1. 导入记录与原作品、来源交付、包 SHA-256 精确匹配；
2. 导入副本已独立重新达到等级 6；
3. 导入者、副本最终验收者和复现回执操作者必须绑定同一认证 subject，且与原作品最终验收 subject
   不同；显示名和请求正文不能改变这一身份判断；
4. 复现记录为不可变 `PASSED`，并由 HTTP 边界重新校验来源。

通过后，原作品增加当前 `REPRODUCTION` 证据并进入 `DELIVERED` 生命周期；复现证据不提高或伪造
0–6 验证等级。

## 7. 依赖失效

每份证据记录当前目标、方案，以及适用的数字场景、代码、参数和结构修订。Creator 在读取或执行
命令前对关系真值重新投影：

- 数字场景变化使静态检查及其下游过期；
- 代码或参数变化使仿真、设备、部署、真机、验收和复现过期；
- 结构变化使结构检查、真机、用户验收和复现过期；
- 目标/方案变化沿既有命令边界使全部相关下游证据过期。

失效不会删除历史证据；记录转为 `STALE`，保存时间和原因，并按剩余的连续有效证据自动降低等级。

## 8. 自动验证范围

M7 自动测试覆盖三种包、manifest/Hash、隐私阻断、篡改拒绝、导入重置、进程中断后的启动恢复、
换包幂等冲突、依赖失效和第二用户复现。
测试只使用临时数据库、Mock/Fake 设备事实和本地 ZIP，不访问真实 Provider、串口、ESP-Claw、Flash
或公开发布入口。真实设备与真人复现属于 M8 外部验收。
