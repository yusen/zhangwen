# 核心工作流

## 创建项目

1. 用户输入创意。
2. 主路由生成项目名称、初始专家、推荐专家和原因。
3. 用户调整专家。
4. 创建 Project。
5. 创建已选专家工作区和独立对话。
6. 保存原始创意为 proposed fact。
7. 协调器生成第一个 PendingItem。
8. 打开初始专家对话。

## 专家对话

1. 保存用户消息。
2. ContextAssembler 组装最小必要上下文。
3. AgentRuntime 调用当前专家。
4. 校验响应。
5. 保存助手消息。
6. 根据响应执行：
   - 创建草稿
   - 提出共享事实
   - 调用 Skill
   - 提出交接
   - 请求用户确认
7. 协调器刷新任务、冲突和唯一事项。

## Skill 调用

1. Agent 提交结构化 SkillRequest。
2. SkillRuntime 校验输入。
3. 根据风险策略请求确认。
4. ToolRunner 执行。
5. 保存 SkillRun 和 ToolRun。
6. 生成结果或产物草稿。
7. 返回当前专家对话。

## 专家交接

1. 发起专家创建 Handoff。
2. 协调器检查接收专家是否已加入项目。
3. 生成最小交接包。
4. 接收专家接受后创建任务。
5. 交接完成时记录输出和相关产物。
6. 不复制整个聊天历史。

## 产物确认

1. 专家生成 draft。
2. 用户或规则将其置为 pending_confirmation。
3. 用户确认后生成正式版本。
4. 更新共享事实或项目决策。
5. 协调器遍历依赖图。
6. 标记受影响的旧下游产物 outdated。
7. 生成新的任务和 PendingItem。
