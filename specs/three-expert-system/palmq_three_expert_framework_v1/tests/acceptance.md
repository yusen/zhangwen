# 验收测试

## 路由

1. “我不知道做什么项目” → 问题引导师。
2. “ESP32读取DHT22并上传MQTT” → 智能工程师。
3. “设计一个ESP32外壳并导出STL” → 结构工程师。
4. “做智能花盆，代码和外壳都要”且需求模糊 → 初始问题引导师，推荐三师。
5. 用户明确选择结构工程师 → 尊重选择。

## 独立工作区

1. 三师拥有不同 threadId。
2. 切换专家不串写消息。
3. 私有草稿不自动成为共享事实。
4. 已确认事实可被相关专家读取。
5. 不注入完整无关聊天。

## 协调器

1. 同一项目最多一个 highlighted PendingItem。
2. 安全事项高于普通事项。
3. 阻塞两位专家的事项高于只影响一位的同级事项。
4. 上游产物新版本确认后，下游旧依赖产物变 outdated。
5. 旧版本不删除。

## 迁移

1. 四类旧角色均可映射。
2. 创想家和教育家旧线程不合并。
3. 旧项目可打开。
4. 旧产物保留来源角色。
5. 迁移重复执行不会重复创建工作区或线程。

## UI

1. 前台只显示三位专家。
2. 中央工作区始终存在。
3. 对话内可显示选项卡和方案卡。
4. 右侧工作只突出一个事项。
5. 产物和设备面板不替代中央对话。
